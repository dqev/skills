# Draw Icons

Author: Dev Chauhan (@dqev)
Repository: https://github.com/dqev/skills

Icon sets achieve consistency through strict geometric rules, shared component parts, and visual inspection of rendered raster tiles. Follow the project DNA, reuse verified parts, and inspect visual renders before reporting completion.

Each project defines its visual language in `icons.yaml` at the project root. All icon files reside in the directory specified by `dir`:

```
<dir>/                 e.g. src/components/icons or src/icons
  source/              Source SVGs: one SVG per icon plus parts/. Geometry only. Edit these.
  <name>.svg           Compiled SVGs generated by build. Never edit manually.
```

Style (`outline`, `duotone`, or `filled`), stroke width, corner families, and grid boundaries are locked in `dna`.

---

## The CLI

Execute from the project root:

```bash
node scripts/icons.js <command>
```

| Command | Action |
|---|---|
| `check` | Validates `icons.yaml`, missing required fields, broken codebase imports, and unsupported display sizes. |
| `shape rect X Y W H [R]` | Generates rounded rectangle path data in the project corner family. |
| `shape poly "x,y x,y ..." [--r R] [--closed]` | Generates rounded polyline/polygon path data. Use to avoid manual tangent math. |
| `lint [names\|all]` | Runs geometric validation (clearance, padding, kinks, radii, angles, detail budgets). |
| `render <names>` | Generates a construction sheet PNG in the temporary review folder with real-pixel enlargements. |
| `sheet [names\|all]` | Generates consistency sheet PNG with real-pixel side-by-side tiles and blurred optical mass comparison. |
| `preview <template.html> [--candidates a.yaml,b.yaml]` | Inlines icons into an HTML template of the product UI for side-by-side candidate comparison. |
| `build` | Runs full linting, checks imports, and compiles all source SVGs into production SVGs in `<dir>/`. |

## Step 1: Project Setup and Validation

Run `check`:

```bash
node scripts/icons.js check
```

1. If `icons.yaml` is absent:
   - Read `references/setup-guide.md`.
   - Inspect project dependencies, UI border radii, typography, and existing icon usages.
   - Present concrete multiple-choice options for product description, personality, target directory, and style.
   - Generate candidate looks and write `icons.yaml` upon approval.
2. If `icons.yaml` exists:
   - Proceed to Step 2.
   - Review any reported code problems (broken imports or invalid display sizes).
   - Treat `dna` settings as project law. Never change DNA without user confirmation.

## Step 2: Draw or Modify Icons

Before drawing, consult:
- `references/design-rules.md` (geometric laws, centrelines, clearances, keylines).
- `references/icon-recipes.md` (exact coordinates for standard icons and base parts).
- `references/svg-specs.md` (file structure, pure geometry requirements, silhouette and detail roles).

Process icons in focused batches of 1 to 6 icons:

1. Check existing assets:
   - Search `<dir>/source/` for existing icons and `data-aliases` matches.
   - If changing an existing metaphor, update the existing file or draw a new source and transfer aliases.
2. Select metaphor:
   - Depict the object rather than the abstract action.
   - Use established universal conventions (gear for settings, bell for notifications, magnifier for search).
   - Check `avoid` rules in `icons.yaml`.
3. Plan geometry and write source SVG:
   - Match the primary shape to its keyline (circle 20, square 18, portrait 16x20, landscape 20x16).
   - Reuse verified parts from `<dir>/source/parts/` (`document.svg`, `person.svg`, modifier badges).
   - Use `node scripts/icons.js shape rect ...` and `shape poly ...` for corners.
   - Write pure geometry to `<dir>/source/<name>.svg`. Never include `stroke`, `fill`, `class`, or `<g>` tags.
   - In duotone or filled sets, assign `data-role="silhouette"` to body outlines and `data-role="detail"` to internal cutouts.
4. Execute linting:
   - Run `node scripts/icons.js lint <name>`.
   - Resolve all reported errors and warnings. If a warning reflects deliberate design intent, add a documented waiver (`data-waive-<rule>="reason"`).
5. Visual review:
   - Run `node scripts/icons.js render <batch>` and inspect the output PNG.
   - Confirm legibility on the 16px enlargement tile.
   - Confirm that clearances remain open and silhouettes read clearly.
6. Batch consistency check:
   - Run `node scripts/icons.js sheet <batch> <neighbors>`.
   - In the blurred row, verify that optical mass matches adjacent icons.
7. Compile icons:
   - Run `node scripts/icons.js build`.

## Step 3: Wire Icons into Product UI

1. Import compiled SVGs inline:
   - Built files use `currentColor` to match typography colors.
   - Ensure the project uses an SVG component loader (Vite: `?react` or `vite-svg-loader`; Next.js: SVGR; Svelte: `?raw`).
2. Replace old icon instances:
   - Update target components (e.g. sidebar, tab bar, header).
   - Retain existing classes, accessibility labels, and wrapper elements.
3. Preserve interactive states:
   - Where the UI alternates between outline and solid states (e.g. active tab), use `<name>-filled.svg` created with `data-style="filled"`.
4. Ensure accessibility:
   - Standalone icon buttons must have `aria-label`.
   - Decorative icons beside text must include `aria-hidden="true"`.
5. Run verification:
   - Execute `node scripts/icons.js check` to verify zero broken imports or invalid sizes.

---

## Step 4: Report Results

Provide a concise summary:
- List of created or updated icons and their metaphors.
- File locations (`<dir>/source/` and `<dir>/`).
- Modified UI files and components where icons are wired in.
- Any applied lint waivers and their technical justification.
